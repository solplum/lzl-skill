# 状态与真实环境验证

仅在数据库、持久化、共享环境或外部副作用影响本次结论时使用。以下用于设计未来执行，不授予当前 agent 写入权限。

## 选择环境，而不是按名称放行或否决

先查连接配置和调用链，弄清实际目标、租户／库／表／记录范围、用户、队列／回调／支付／邮件等外部出口。不要打印密钥或直接拉取真实敏感数据来证明连通性。复用已核实的授权与环境事实，只问会改变决策的缺口。

优先在能保留关键语义的本地服务、容器、克隆或隔离测试环境重现。保留本次重要的数据库引擎／版本、约束、事务隔离、字符排序、配置或数据分布；无需追求与生产无关的完全同构。若依赖沙箱无法证明真实集成的重要性质，写清差距、必要实测、责任人和完成时机，不把沙箱结果外推成全链路通过。

已明确获准使用隔离的项目在线测试库且实际影响清楚，可以安排写入和清理。共享真实环境的测试也按具体效果、隔离措施与权限判断，不做“所有在线操作禁止”或“有连接就能写”的推断。授权不明确的依赖项先准备好，待确认再执行，不阻塞无关验证。

## 对每类状态变化建立可核验的闭环

在计划中按实际需要写明：

- **对象与前态**：本次专属记录、租户、运行标记、关联项及相关业务状态；避免借用真实用户数据。是否存在通知、计费、审计或其他不能撤回的效果？
- **预期变化与隔离**：哪些变化是测试目的，哪些不该发生；如何避免影响他人读写或后台任务。事务回滚只能覆盖事务内效果，不自动撤销队列、回调或外部扣款。
- **清理的范围与授权**：清理也是写入，事前纳入许可。优先使用项目支持的清理路径或仅针对本次运行创建对象的有条件操作；既不能按宽泛名称批量删除，也不能覆盖并发更新。清理前重新核对所有权／版本／状态，存在冲突就停止相关清理并协调。
- **恢复后的业务不变量**：例如测试预留已解除、可售库存恢复、无孤立关联项、无待发外部任务且真实业务记录未被改变。恢复业务状态，而非默认要求文件／数据库字节完全一致；无实际约束的日志、更新时间、自增序列变化可以保留。审计、财务或幂等规则要求这些字段不变时，则把该要求纳入断言。
- **失败与不确定结果**：超时不等于未执行。先按请求标识、幂等键或可靠状态查询核对，再决定重试；无法确认时暂停相关写入并交接，不盲目再提交或再删除。清理／恢复失败时保留证据、停止可能扩大影响的后续写入，交由相应负责人处理，不临场尝试更大范围破坏性修复。

清理完成本身也须有验证证据，不用“最后 rollback 一下”替代具体恢复路径。没有持久化变化的测试无需套用上述所有字段。

## 高风险真实操作：回滚口号不够

不要为了“测得真实”默认在真实共享数据上 DROP、TRUNCATE、批量覆盖、不可逆转换或危险迁移。优先在有代表性的克隆上验证，并检查关键语义、数据规模及锁／停机行为是否足够真实。

只有业务确需在真实目标做这类操作时，才把它作为明确的未来条件步骤；不能因声称“有备份／可回滚”就执行或判定安全。开始前需要：

1. 针对具体目标、动作、窗口和影响的授权，以及必要协作；一般测试权限不替代它。
2. 可验证的恢复能力：备份是否覆盖相关数据及依赖、时间点是否合适；可用的恢复／还原演练证据；执行恢复所需权限、负责人、步骤和时间是否满足实际要求。
3. 不能恢复的外部效果、演练未覆盖的差距及实际处置决定；不可伪造已有演练或保证一定能恢复。
4. 明确中止点和失败响应。恢复能力未知就标记该步骤阻塞，继续克隆验证等独立工作，而不是降低必要测试标准或临时破坏数据。

这里的额外要求针对实际高风险操作，不把普通隔离测试数据写入升级成全套灾难恢复项目。
